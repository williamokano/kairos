# 04 — Running agent CLIs

The thing the binary actually does: launch `claude` / `codex` / `gemini` as a child process in a
workspace, feed it a task, get **schema-valid JSON** back, and record everything.

---

## The file contract

Every actor — an LLM CLI, a shell script, a Go builtin, a human — sees the same five paths. Any program
that reads a JSON file and writes a JSON file is an actor.

```text
~/.kairos/work/run_01J8/repo/          ← the agent's cwd; a --reference clone
├── <the repo>
└── .kairos/                            ← inside the confinement boundary, so ONE writable root
    ├── input.json                      resolved, validated inputs (immutable once executing)
    ├── output.json                     the agent writes this. the FILE is what gets read.
    ├── output.schema.json              $refs resolved inline
    ├── prompt.md
    ├── progress.jsonl
    └── context/
        ├── MANIFEST.json               digest per file — makes "what did it see" exact
        ├── constitution.md             materialised 0444 from project memory
        ├── AGENTS.md
        ├── findings.json
        ├── decisions.json
        └── untrusted/issue-421.md      ← content from outside is DATA, fenced and labelled

~/.kairos/work/run_01J8/
├── home/                               ← HOME for every process of this run
│   └── .gitconfig                      0444: no credential helper, no hooks, dead pushurl
└── nex_01/
    ├── stdout.log stderr.log           files, not pipes — see below
    └── proc.json                       {pgid, nonce, startedAt}
```

`.kairos/` lives *inside* the workspace deliberately: one writable root means path confinement is a
single-prefix rule, and it is exactly the shape Codex's `workspace-write` sandbox already permits.
It goes in `.git/info/exclude`, not `.gitignore` — the latter is repo content the agent may legitimately
edit.

### The environment is constructed, never inherited

```text
PATH HOME LANG TZ
KAIROS_RUN_ID KAIROS_NODE_ID KAIROS_NODE_EXEC_ID KAIROS_SESSION_ID
KAIROS_DIR KAIROS_OUTPUT KAIROS_SCHEMA KAIROS_SOCK KAIROS_DEADLINE
TERM=dumb NO_COLOR=1 CI=1 GIT_TERMINAL_PROMPT=0
+ the model API key, and per-actor declared toolchain vars (GOFLAGS, GOMODCACHE, …)
```

No `GH_TOKEN`, no `GITHUB_TOKEN`, no `JIRA_*`, no `AWS_*`, no `SSH_AUTH_SOCK`.

**Setting `HOME` to a per-run directory is the highest-value single line here.** The child does not find
`~/.ssh`, `~/.aws`, `~/.kube`, `~/.netrc`, or your shell history *at the path every tool looks*. It is
not a security boundary — absolute paths still work — but it converts "the agent read your AWS keys
because every tool checks `$HOME`" from an **accident** into an **intent**, and accidents are the top of
the likelihood table. Real toolchain caches are re-pointed explicitly so builds stay fast.

`KAIROS_DEADLINE` is passed in so the agent can budget its own work rather than being killed mid-thought.

## Command shapes

Every flag below is **probed, not assumed**: at actor registration the engine runs `<cli> --version` and
`--help`, records the supported flag set, and degrades gracefully. These CLIs change monthly and a
binary that hardcodes flags rots.

### Claude Code

```bash
cd ~/.kairos/work/run_01J8/repo && \
CLAUDE_CONFIG_DIR=~/.kairos/agents/claude/backend-engineer \
HOME=~/.kairos/work/run_01J8/home \
TERM=dumb NO_COLOR=1 CI=1 GIT_TERMINAL_PROMPT=0 \
claude -p \
  --session-id 019bf3c1-8a11-7c2e-9f04-2d55aa9e1b30 \
  --output-format stream-json --verbose \
  --model sonnet \
  --permission-mode acceptEdits \
  --add-dir ~/.kairos/work/run_01J8/repo \
  --settings   ~/.kairos/work/run_01J8/nex_01/settings.json \
  --mcp-config ~/.kairos/work/run_01J8/nex_01/mcp.json --strict-mcp-config \
  --allowedTools "Read,Grep,Glob,Edit,Write,Bash(go build:*),Bash(go test:*),Bash(git add:*),Bash(git commit:*),Bash(kairos check-output:*)" \
  --disallowedTools "Bash(git push:*),Bash(gh:*),WebFetch" \
  --max-turns 80 \
  < .kairos/prompt.md
```

Five details that matter:

- **Prompt on stdin, not argv.** Argv appears in `ps` for every process on the machine, and prompts
  routinely contain issue bodies and file excerpts.
- **`--session-id` is generated by us**, so the session identity is known *before* the process starts
  and survives a crash mid-first-turn. Resume is `claude -p --resume $SID`.
- **`--verbose` is required** for `stream-json` to emit the full event stream rather than one result
  object.
- **`--settings` points at a kairos-generated file outside the workspace, mode 0444**, carrying the
  `PreToolUse` hook that is the real pre-execution enforcement point. With `--strict-mcp-config`, no
  ambient `~/.claude/settings.json` and no project `.claude/settings.json` the agent just wrote get
  loaded — and no MCP server holding your Jira token gets attached to a coding node. Default: **no MCP
  servers unless declared.** An inherited MCP config is a far shorter path to damage than `bash`.
- **`--permission-mode acceptEdits` is no longer free.** It was defensible in the original design
  *because of the microVM*. Here it is scoped by `--add-dir` to the workspace, with push/gh/network in
  `--disallowedTools`, and `bypassPermissions` is reachable only behind an acknowledgement string.

### Codex — and it is the safest option on an unsandboxed host

```bash
CODEX_HOME=~/.kairos/agents/codex/backend-engineer \
codex exec --json \
  --cd ~/.kairos/work/run_01J8/repo \
  --sandbox workspace-write \
  --output-last-message .kairos/last-message.txt \
  --output-schema .kairos/output.schema.json \
  - < .kairos/prompt.md
```

`--sandbox workspace-write` is Seatbelt on macOS and Landlock+seccomp on Linux, enforced **by the agent,
before the tool call, with no root and no kairos code**. It is the single best guardrail available in
this variant and it costs one flag. `read-only` for reviewer nodes gives back structural incapability —
a reviewer that *cannot* write cannot "helpfully fix" what it found. Never
`--dangerously-bypass-approvals-and-sandbox`.

### Local models — the only path with a guarantee

```bash
curl -s http://127.0.0.1:11434/api/chat -d @- <<'JSON'
{"model":"qwen2.5-coder:7b","stream":false,
 "format": { …the node's outputSchema, verbatim… },
 "messages":[{"role":"system","content":"…"},{"role":"user","content":"…"}]}
JSON
```

Ollama's `format: <json-schema>` (and the OpenAI-compatible `response_format: {type: json_schema,
strict: true}`) do **constrained decoding**: the output is schema-valid by construction, with no repair
path and no failure mode. It is free, runs in seconds, and needs no subprocess at all. Route every
`classify` / `triage` / `route` / `interpret` node here.

## Getting schema-valid JSON out, and what happens when you don't

The order inverts from the distributed design, because the thing that makes the cheap path work — a
validator on the agent's `PATH` — is now trivially available: **it is the same binary the user already
installed.**

**Stage 0 — constrain if you can.** Local/OpenAI-compatible `format`, or Codex `--output-schema`. Done;
no repair path exists.

**Stage 1 — file drop plus in-loop self-validation.** The primary path for agent CLIs. Appended to every
prompt, verbatim:

```text
## Output contract — read this last and obey it exactly
Write your result to $KAIROS_OUTPUT. It must validate against $KAIROS_SCHEMA.
Do not print the JSON in your reply; the FILE is the only thing read.

Before you finish, run:  kairos check-output
It exits 0 on success, or 1 and prints one line per violation as
  <json-pointer>: <message>
Fix the file and re-run until it exits 0. If you cannot satisfy the schema, write
{"$needsHuman": "<what you need>"} to the file and exit.
```

`kairos check-output` is a subcommand of the same binary, reading `$KAIROS_OUTPUT` / `$KAIROS_SCHEMA`
from the env we set, and it is in `--allowedTools` so no permission prompt fires. **This converts a
schema miss from a node failure into a fix the agent makes inside its own loop** — the single highest-
leverage trick in the design, and locally it costs nothing to provide.

`{"$needsHuman": "..."}` is reserved: the engine maps it to a `NeedsHuman` outcome and creates a human
task. That is how an agent asks a question without a process blocking on stdin.

**Stage 2 — one repair turn, in-session.** File missing or invalid, and the runner supports resume:

```bash
claude -p --resume $SID <<EOF
Your output at $KAIROS_OUTPUT does not validate:
  /tasks/0/criteria: expected array, got string
  /branch: required property is missing
Fix the FILE only. Change no code. Run \`kairos check-output\` until it exits 0.
EOF
```

Strictly better than the distributed design's "cheap model converts the transcript tail": the original
session still holds full context, and resume costs one process spawn. **One attempt only** — a second
means the schema or the node is wrong. Emits `output.repair.attempted{errors}`.

**Stage 3 — extraction**, only when the runner cannot resume (Gemini): one call to the local model with
*constrained decoding* over the raw output. Never silent; emits `node.output.extracted{model}`. Pleasing
asymmetry: the extractor cannot itself produce invalid JSON.

**Stage 4 — fail.** `node.output.invalid{validationErrors, rawOutputArtifact}`. The transcript and raw
output are kept as artifacts. `retryOn` includes `schema-invalid` by default, and `retry.mutate` is the
escalation ladder: attempt 2 on a stronger model, attempt 3 on a **different CLI against the same typed
contract**. That last one is L3 paying for itself.

Errors are rendered as JSON-Pointer lines, **capped at 20 with a count**. An agent handed 400 validation
errors will rewrite the world.

Never: pass unvalidated data downstream, infer intent, or coerce types. The one thing the engine must
not do is the thing every framework does — accept "close enough" JSON.

## Sessions: two concepts, never conflated

| | **Kairos Session** | **The CLI's native session** |
| --- | --- | --- |
| identity | our ULID | their UUID |
| lifetime | `affinity: execution / node / run` | one invocation, resumable by id |
| contents | typed: turns, tokens, cost, state | the agent's own transcript JSONL |
| authoritative for | accounting, gates, cost | the model's context |

`exact` resume fidelity dies with the hypervisor. Two remain:

- **`native`** — the CLI resumes its own conversation (`claude --resume`, `codex exec resume`). The
  transcript is intact; only the process was lost. Better than the old `logical`, worse than `exact`.
- **`digest`** — rehydrate from run memory plus a summarised transcript, re-inject `context/`, restate
  the task before the first turn. Always **recorded**, so a later oddity is attributable rather than
  mysterious.

**The path-keying trap, which will bite you.** Claude Code keys stored sessions by a slug derived from
the *cwd*. If a node retries in a fresh workspace at a new path, `--resume <id>` silently finds nothing
even though the id is valid. Two mitigations, use both: keep the workspace path a function of
`(runID, repo)` so it is stable across attempts (`freshWorkspace` deliberately breaks this, which is
correct — a fresh workspace *should* mean a fresh session), and record the resume directory so a failed
resume emits `session.resume.failed` and falls back to `digest` rather than silently starting over.

Idle timeout rises from 30m to 2h: an idle session now costs one idle process, not 4 GB of VM.

## Accounting, timeouts, cancellation

**Cost, in priority order, with the fallback visible:**

1. **The CLI's own reported total** — authoritative, because it knows cache pricing and
   subscription-vs-API. Record `costSource: runner`.
2. **Our price table × reported tokens.** Record `costSource: computed, priceTableVersion: N`.
3. **Nothing reported** → `costSource: unknown`, cost 0, and `session.cost.unavailable` emitted once.
   Do **not** estimate from character counts; a made-up number in a budget check is worse than a missing
   one.

Enforcement is **pre-emptive**, which is the main reason to parse the stream at all: after each turn,
if `spent + estimatedNextTurn > maxCostUSD`, close stdin, `SIGTERM` the group, append
`CostLimitReached`. A post-hoc report is an invoice.

**Four independent backstops:**

| | Mechanism |
| --- | --- |
| node timeout | `time.AfterFunc(deadline)` → terminate the process **group** |
| turn-idle timeout | reset on every byte from either stream; default 5m. A wedged agent emitting nothing is a different failure from a slow one emitting tokens, and only the stream distinguishes them |
| max turns | the CLI's own `--max-turns`; hitting it **fails** the node rather than returning a half-finished result that looks complete |
| resource watchdog | Linux: `systemd-run --user --scope -p MemoryMax=8G -p CPUQuota=400%`. macOS: **no equivalent** — poll RSS and terminate over a threshold, and call it a monitor, not a limit |

**Streaming.** Raw bytes to `stdout.log` **first**, parse second — if the parser panics on a shape from
a CLI upgrade, you still have the transcript (recover, emit `session.stream.unparsed`, keep going).
Progress lines are **coalesced** into one event per 250ms or 64 entries: a 30-minute session emits
thousands of tool-call lines, and one event each turns a 2.5 GB/year database into a 40 GB one.
Milestones, compactions, and token totals always get their own event.

**Compaction is the signal to watch.** It is the leading indicator of the original problem — the agent
forgetting the rules — and it drives context re-injection plus a metric. Detect it per runner from the
stream; where a runner reports nothing, infer it from input tokens dropping >50% between turns and mark
`inferred: true`. When re-injecting, write `context.new/` and `rename` the directory: a
partially-rewritten context directory read mid-turn is a monthly bug that looks like a model failure.

**Cancellation** is the ordered sequence in [`01-architecture.md`](01-architecture.md): close stdin →
`SIGTERM` the group → grace → `SIGKILL` → drain the log files → record. `cmd.Wait()` is called exactly
once per child behind a `sync.Once`, because a leaked `Wait` leaks a zombie and a pipe fd pair, and 200
runs later the daemon hits `EMFILE`.

## The credential design, and why it is the best guardrail here

The secret *broker* mostly evaporates: brokering a value over a socket to a process that can read the
same value off disk as the same uid is theatre, and claiming otherwise would be worse than not doing it.

What replaces it is **capability, not permission.** The agent commits; **kairos pushes.**

```bash
# per-run gitconfig, written by kairos at 0444
[user]        name = Kairos (backend-engineer); email = kairos+agent@localhost
[credential]  helper =                                  # empty: disables inherited helpers
[core]        hooksPath = /dev/null
              askPass = /usr/bin/false
[remote "origin"] pushurl = kairos-blocked://denied
```

The workspace's `origin` is the **local mirror**, not GitHub. The agent can `fetch`, `commit`, and even
`push` — to a local bare repo, which is reversible and exactly what "hand back a branch" needs. Kairos
then pushes mirror → GitHub as a declared **effect**, in a different process, with a different
environment populated from the keychain *after* a policy check and (for protected refs) a recorded human
decision.

Cost: one indirection. Value: `git push --force origin main` by a confused agent becomes a local no-op
you can `git reflog` your way out of. **This is the highest-value guardrail in the whole variant and it
involves no sandbox at all.**

Default all agent-visible branches to `kairos/<runID>/…` — deletable, therefore compensable — and make
promotion to a real branch a separate, gated, `irreversible: true` effect. That one convention converts
the most common destructive action in the system from irreversible into reversible.
